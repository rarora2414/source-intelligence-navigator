# Validation and limits

## Executed for 0.1.0

- Skill frontmatter and unfinished-scaffold validation.
- Local Markdown-reference existence and public-file privacy review.
- Manual instruction/example review for supplied versus independently inspected evidence, inaccessible current sources, version conflicts and proportionate scope.

The worked example is authored expected behavior using fictional supplied documents. It is not a live research result or a separate model evaluation. No external source claims or speed/quality benchmark results are asserted.

## Not established

No multi-provider agent benchmark, automatic browser integration, live source-connectivity test or real-world adoption study. Access, model behavior and the user's domain affect results.

## Try these scenarios

- No browsing access, only an old supplied document: mark current status unverified.
- An official v2 specification conflicts with a v1 blog: compare version and authority before resolving.
- One small question: return a small answer, not a mandatory full pack.
- A recurring question already has a source router: reuse it and check its refresh trigger.
- A source is inaccessible: preserve the gap instead of inventing a citation.
