# Source Intelligence Navigator

Help someone know where to look, what to trust for a particular question, and when to check again. Optimize for useful coverage rather than the length of a reading list.

## Start from the question

Identify what the person needs to decide, explain or do. Separate foundational learning, current facts and consequential decisions. Use the existing source map if one exists. Ask only for a missing choice that materially changes the research; otherwise state a reasonable scope assumption.

For a single question, a short answer plus its best source may be enough. For a field, build [an expert pack](assets/EXPERT_PACK.template.md) covering the vocabulary, actors, normal workflow, decisions and common traps. Do not create a large syllabus for a small lookup.

## Select sources by their job

Choose the smallest set that covers the actual questions:

| Source role | Use it for |
| --- | --- |
| Anchor | A structured overview and vocabulary |
| Controlling | The applicable rule, primary specification or authority for a consequential decision |
| Operating | Instructions, examples and templates for doing the work |
| Current status | Live documentation, notices, release notes or records that can change |
| Specialist | A gap the other sources do not cover |

One source may fill multiple roles. Prefer original research, official documentation and primary records for factual claims. A popular overview can explain a rule without controlling it. An official source may still be outdated or outside the applicable version, jurisdiction or population.

Rank candidates by authority **for this question**, scope fit, freshness, inspectability and lookup effort. Do not manufacture numeric credibility scores. Add a source only when it closes an identified gap or makes recurring lookup meaningfully faster.

## Build the source router

For each recurring question, record: first source and exact section/search; fallback; why this route fits; version/jurisdiction if relevant; whether live checking is needed; last inspected date; refresh trigger; supported claim; limits or unresolved conflicts.

Distinguish **inspected**, **supplied but not independently inspected**, **discovered but unread**, and **inaccessible**. Search snippets locate sources; they do not prove the whole page supports the answer. Cite the inspected source near its claim. Do not invent links, quotations, dates or page numbers. Old saved answers are routes, not proof of present facts.

When sources disagree, compare authority, applicability, versions and dates before resolving. Keep the conflict visible if unresolved. For medical, legal, financial, security or other consequential decisions, use current controlling evidence and state limits; a reference pack does not confer professional qualifications.

If web or private-source access is unavailable, build a clearly labeled provisional router from supplied material. State which claims cannot be checked. Do not silently substitute memory for a requested live check.

## Teach through the route

Provide a short field map, minimum source stack, question-to-source router, useful vocabulary, practical sequence, one worked example and unresolved questions. Explain why each route works so the person can use it independently. Adapt the depth to their goal.

Save reusable discoveries only when requested, in the existing project/source record or selected destination. Preserve successful search terms, exact sections, dead ends, verification date and refresh triggers. Before editing, reread and reconcile intervening changes; verify the saved result. Do not upload private source contents or overwrite unrelated notes.

## Stop when coverage is sufficient

Stop gathering when each in-scope question has a suitable inspected route or an explicit gap. Return the answer/next action first, then the compact pack. Separate source-backed fact, inference, hypothesis and recommendation. Avoid claiming exhaustive expertise or guaranteed time savings.

Optional: link routes into a Project Book's sources and task prerequisites, using the same IDs and existing record. This skill works without that companion and does not start background monitoring or authorize outreach.
